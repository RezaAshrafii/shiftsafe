# فاز ۷ — آزمون کنترل‌شده‌ی distribution shift

## هدف

در فاز قبلی interval روی داده‌ی مرجع ساخته شد. حالا همان مدل و همان radius را روی test تغییرکرده امتحان می‌کنیم تا ببینیم خطا و coverage چه تغییری می‌کنند.

## shiftهای فعلی

### تغییر میانگین (`mean`)

به featureهای عددی یک مقدار ثابت اضافه می‌شود. این می‌تواند تغییر سطح سنسور یا تغییر operating regime را به‌صورت مصنوعی شبیه‌سازی کند.

### تغییر مقیاس (`scale`)

featureهای عددی در یک ضریب مثبت ضرب می‌شوند. این می‌تواند تغییر دامنه یا کالیبراسیون سنسور را شبیه‌سازی کند.

هر دو روش deterministic هستند و داده‌ی اصلی را تغییر نمی‌دهند.

## نکته‌ی مهم آزمایش

مدل فقط روی train آموزش می‌بیند. radius فقط از calibration reference ساخته می‌شود و هنگام shift دوباره fit یا calibrate نمی‌شود. بنابراین می‌توانیم ببینیم همان اعتمادی که روی reference داشت، زیر تغییر داده چه وضعی پیدا می‌کند.

## خروجی گزارش

گزارش دو بخش دارد:

- `reference`: point error، baseline error، coverage و width روی test عادی؛
- `shifted`: همان معیارها روی test تغییرکرده.

در هر دو بخش baseline نیز حفظ می‌شود تا افت یا بهبود مدل نسبت به روش ساده دیده شود.

برای هر ردیف نیز prediction مرجع، prediction تغییرکرده، دو بازه و وضعیت پوشش ذخیره می‌شود. ستون‌های shift‌شده و `coverage_gap` نیز در خروجی ثبت می‌شوند تا آزمایش قابل بازتولید باشد.

## محدودیت و مرز ادعا

این shiftها مصنوعی و کنترل‌شده‌اند. نباید آن‌ها را داده‌ی واقعی شرکت یا شاهد قطعی رفتار صنعتی معرفی کرد. فاز بعدی باید با داده‌ی عمومی نزدیک به یک use case واقعی یا داده‌ی شریک تکرار شود.

از نظر مفهومی، این فاز فقط `covariate shift` را شبیه‌سازی می‌کند: featureها تغییر می‌کنند اما target مرجع ثابت نگه داشته می‌شود. تغییر رابطه‌ی feature و target یا `concept drift` هنوز آزمایش نشده است.

## توضیح شفاهی آماده

«یک مدل و interval را روی داده‌ی مرجع ثابت نگه داشتم. سپس فقط featureهای test را با تغییر میانگین یا مقیاس جابه‌جا کردم و دوباره error، coverage و width را اندازه گرفتم. اگر coverage افت کند، نشان می‌دهد calibration مرجع در برابر این نوع shift پایدار نیست. این آزمایش مصنوعی است و ادعای عملکرد واقعی شرکت نیست.»
