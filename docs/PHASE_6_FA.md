# فاز ۶ — prediction interval و split-conformal baseline

## مسئله‌ای که حل می‌کنیم

پیش‌بینی نقطه‌ای فقط یک عدد می‌دهد. اما در تصمیم واقعی باید بدانیم خطای احتمالی این عدد چقدر است. این فاز به‌جای یک عدد، یک بازه می‌سازد:

```text
lower ≤ مقدار واقعی احتمالی ≤ upper
```

## روش اجرا

داده به سه قسمت تقسیم می‌شود:

1. `train`: آموزش مدل خطی؛
2. `calibration`: اندازه‌گیری خطاهای مدل روی داده‌ای که برای آموزش استفاده نشده؛
3. `test`: ارزیابی نهایی بازه.

از قدرمطلق خطاهای calibration یک شعاع ساخته می‌شود. سپس برای پیش‌بینی test این بازه ساخته می‌شود:

```text
prediction - radius
prediction + radius
```

## دو معیار اصلی

- `coverage`: چند درصد مقدارهای واقعی داخل بازه افتاده‌اند؛
- `mean_width`: میانگین پهنای بازه.

خروجی برای هر ردیف test نیز `actual`، `prediction`، `lower`، `upper` و `covered` را نگه می‌دارد تا معلوم باشد کدام نمونه‌ها خارج از بازه بوده‌اند. علاوه بر آن، خطای نقطه‌ای مدل و baseline میانگین هم گزارش می‌شوند.

بازه‌ی خیلی باریک ممکن است مقدارهای واقعی را پوشش ندهد. بازه‌ی خیلی پهن ممکن است از نظر تصمیم کاربردی نباشد. بنابراین هر دو معیار باید با هم دیده شوند.

## پارامتر alpha

اگر `alpha=0.1` باشد، coverage اسمی برابر `0.9` یا ۹۰ درصد است. این عدد هدف calibration روی reference data است، نه تضمین عملکرد در داده‌ی تغییرکرده.

اختلاف coverage تجربی و coverage اسمی با `coverage_gap` گزارش می‌شود. اگر calibration کمتر از سه ردیف داشته باشد، اجرا متوقف می‌شود؛ چون radius با نمونه‌ی بسیار کوچک قابل اتکا نیست.

## محدودیت بسیار مهم

این پیاده‌سازی فقط split-conformal برای regression است. هیچ تضمینی برای distribution shift، سایت جدید، فصل جدید یا شرایط عملیاتی جدید ادعا نمی‌کند. اگر توزیع داده عوض شود، coverage باید دوباره اندازه‌گیری شود.

## توضیح شفاهی آماده

«در فاز شش، داده را به آموزش، calibration و test جدا کردم. مدل روی train آموزش می‌بیند، خطاهای calibration برای ساخت شعاع عدم‌قطعیت استفاده می‌شوند و روی test یک بازه‌ی پیش‌بینی ساخته می‌شود. سپس coverage و width را گزارش می‌کنم. این روش روی داده‌ی مرجع قابل ارزیابی است و به‌تنهایی تضمین عملکرد در distribution shift نیست.»
